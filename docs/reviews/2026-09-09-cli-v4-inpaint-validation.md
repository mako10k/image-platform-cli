# V4 inpaint increment validation

Date: 2026-09-09. Authority: accepted CLI requirement v6 and owner's implementation continuation.

Implemented `image4 edit inpaint` through POST /v4/inpaints only. The supported fixed profile,
mask/image input, seed and safety mode remain available. Validation checks input and mask geometry,
combined size, the fixed inpaint identity, full mask/input/output receipts, returned image bytes,
required headers and requested/effective/outcome safety evidence before output creation.

Shared V4 byte and image-header checks were extracted into image_results; the image-to-image and
inpaint receipts remain independently validated. No v1 implementation or default dispatch change.

Evidence: 173 tests passed; Ruff, strict Mypy, Xenon and Pylint duplicate-code passed. Eleven new
inpaint cases cover the default fixture generated by the real local API, enabled/disabled modes,
receipt/header contradictions and pre-request dimension mismatch. Explicit safety-mode fixtures
are derived local test cases, not live execution observations.

Built a wheel, installed it offline into an isolated environment and verified its inpaint parser
and successful fixture consumption outside the source checkout. No public API call or provider
execution occurred. Coverage matrix v3 records inpaint as V4-bound; 20 other rows remain missing.
